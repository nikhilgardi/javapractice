1. Difference Between ==, equals() and hashCode()

In Java:

  • == checks whether two object references point to the same object.
  • equals() checks logical equality, based on its implementation.
  • hashCode() returns an integer used by hash-based collections to organize objects.

Example 1: Overriding Both equals() and hashCode()

import java.util.Objects;

class Employee {
    int id;
    String name;

    Employee(int id, String name) {
        this.id = id;
        this.name = name;
    }

    @Override
    public boolean equals(Object obj) {
        if (this == obj) {
            return true;
        }

        if (!(obj instanceof Employee)) {
            return false;
        }

        Employee other = (Employee) obj;

        return this.id == other.id
                && Objects.equals(this.name, other.name);
    }

    @Override
    public int hashCode() {
        return Objects.hash(id, name);
    }
}

public class Main {
    public static void main(String[] args) {
        Employee e1 = new Employee(101, "Nikhil");
        Employee e2 = new Employee(101, "Nikhil");

        System.out.println(e1 == e2);
        System.out.println(e1.equals(e2));
        System.out.println(e1.hashCode() == e2.hashCode());
    }
}

Output

false
true
true

Explanation

  • e1 == e2 is false because these are two different objects.
  • e1.equals(e2) is true because their IDs and names match.
  • Their hash codes are equal because the fields used by hashCode() match.

2. What Happens If We Remove name from Both Methods?

Suppose equals() and hashCode() consider only id.

@Override
public boolean equals(Object obj) {
    if (this == obj) {
        return true;
    }

    if (!(obj instanceof Employee)) {
        return false;
    }

    Employee other = (Employee) obj;
    return this.id == other.id;
}

@Override
public int hashCode() {
    return Integer.hashCode(id);
}

For these objects:

Employee e1 = new Employee(101, "Nikhil");
Employee e2 = new Employee(101, "Rahul");

System.out.println(e1.equals(e2)); // true

Why? Because the equality rule now considers only the ID. The names are ignored.

Important: The fields used by equals() determine logical equality. You should implement hashCode() consistently with that equality rule.

3. What If We Remove name Only from hashCode()?

Suppose equals() checks both id and name, but hashCode() checks only id.

@Override
public boolean equals(Object obj) {
    if (this == obj) {
        return true;
    }

    if (!(obj instanceof Employee)) {
        return false;
    }

    Employee other = (Employee) obj;

    return this.id == other.id
            && Objects.equals(this.name, other.name);
}

@Override
public int hashCode() {
    return Integer.hashCode(id);
}

For these objects:

Employee e1 = new Employee(101, "Nikhil");
Employee e2 = new Employee(101, "Rahul");

System.out.println(e1.equals(e2));
System.out.println(e1.hashCode() == e2.hashCode());

Output

false
true

This implementation is valid. Unequal objects are allowed to have the same hash code. This is called a hash collision.

The required contract

  • If equals() returns true, the hash codes must be equal.
  • If hash codes are equal, equals() does not have to return true.

4. What Happens If We Override equals() but Not hashCode()?

Consider the following example:

import java.util.HashSet;

class Employee {
    int id;

    Employee(int id) {
        this.id = id;
    }

    @Override
    public boolean equals(Object obj) {
        if (this == obj) {
            return true;
        }

        if (!(obj instanceof Employee)) {
            return false;
        }

        Employee other = (Employee) obj;
        return this.id == other.id;
    }

    // hashCode() is not overridden
}

public class Main {
    public static void main(String[] args) {
        HashSet<Employee> employees = new HashSet<>();

        employees.add(new Employee(101));
        employees.add(new Employee(101));

        System.out.println(employees.size());
    }
}

Typical output

2

Why?

  • Both employees have the same ID.
  • The overridden equals() method considers them equal.
  • However, the inherited Object.hashCode() usually returns different hash codes for these distinct objects.
  • The HashSet uses the hash code to determine where to look for existing elements. If the hash codes differ, it generally does not compare these objects using equals().
  • Both objects can therefore be retained.

Strictly speaking, different objects are not guaranteed to have different default hash codes. Thus, 2 is the expected result, not an absolute guarantee.

Lesson: When you override equals(), you should also override hashCode().

5. Correctly Overriding Both Methods for HashSet

Here is a corrected implementation:

import java.util.HashSet;

class Employee {
    int id;

    Employee(int id) {
        this.id = id;
    }

    @Override
    public boolean equals(Object obj) {
        if (this == obj) {
            return true;
        }

        if (!(obj instanceof Employee)) {
            return false;
        }

        Employee other = (Employee) obj;
        return this.id == other.id;
    }

    @Override
    public int hashCode() {
        return Integer.hashCode(id);
    }
}

public class Main {
    public static void main(String[] args) {
        HashSet<Employee> employees = new HashSet<>();

        Employee emp1 = new Employee(101);
        Employee emp2 = new Employee(101);

        System.out.println(emp1.hashCode());
        System.out.println(emp2.hashCode());

        employees.add(emp1);
        employees.add(emp2);

        System.out.println(employees.size());

        HashSet<String> set = new HashSet<>();
        set.add("Nik");
        set.add("Nik");

        System.out.println(set.size());
    }
}

Output

101
101
1
1

Explanation

  • Both employees have hash code 101.
  • The HashSet finds the existing employee in the relevant bucket.
  • It calls equals() to compare the two employees.
  • Since their IDs match, equals() returns true.
  • The second employee is treated as a duplicate and is not added.
  • The two "Nik" strings are also treated as duplicates because String already implements equals() and hashCode() appropriately.

6. Why Did Your Earlier Employee1 Example Still Print 2?

Your original code contained this mistake:

if (!(obj instanceof Employee)) {
    return false;
}

Employee other = (Employee) obj;

But your actual class was named Employee1.

The correct implementation is:

@Override
public boolean equals(Object obj) {
    if (this == obj) {
        return true;
    }

    if (!(obj instanceof Employee1)) {
        return false;
    }

    Employee1 other = (Employee1) obj;
    return this.id == other.id;
}

When the class check uses Employee instead of Employee1, the comparison returns false for the Employee1 objects. Even though their hash codes match, equals() does not identify them as equal.

With the corrected class check and hashCode(), the set size becomes 1.

7. How Does HashSet Work Internally?

Conceptually, adding an object follows these steps:

  1. Calculate the hash code. Java uses the hash code to determine the relevant hash bucket.
  2. Look for possible duplicates. The set examines objects in the relevant bucket.
  3. Compare objects. If a possible match is found, equality checks determine whether it is a duplicate.
  4. Decide whether to add. If an equal element already exists, the new element is not added. Otherwise, it can be stored.

Hash collisions can occur, so having the same hash code does not automatically mean two objects are equal.

9. Final Interview Rules to Remember

  • == compares object references, not logical equality.
  • equals() defines logical equality according to the class implementation.
  • hashCode() helps hash-based collections organize objects efficiently.
  • HashSet relies on both hash codes and equality checks.
  • Equal objects must have equal hash codes.
  • Equal hash codes do not guarantee that objects are equal.
  • If you override equals(), override hashCode() consistently.
  • Use the correct class in instanceof checks and casts.
  • Avoid changing fields used by equals() and hashCode() while an object is stored in a HashSet; doing so can make it difficult to find or remove that object.

Golden rule: hashCode() helps locate where to check; equals() determines whether an existing object is logically equal to the new one.
