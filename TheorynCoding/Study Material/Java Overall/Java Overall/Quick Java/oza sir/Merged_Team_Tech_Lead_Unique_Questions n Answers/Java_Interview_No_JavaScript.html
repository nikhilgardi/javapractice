Java is platform-independent because the Java compiler converts source code into bytecode, which can run on any operating system that has a compatible JVM.

Primitive types store values directly, while reference types store references used to access objects.

  • Instance fields are stored as part of their objects.

4.Is Java pass-by-value or pass-by-reference? Demonstrate with an object.

Answer / Notes

Answer

Java always uses pass-by-value. A method receives a copy of the argument's value. For primitives, the actual value is copied. For objects, the reference value is copied.

1. Primitive Example

public class Main {
    static void changeValue(int x) {
        x = 100;
    }

    public static void main(String[] args) {
        int number = 10;

        changeValue(number);

        System.out.println(number);
    }
}

Output

10

Explanation

number = 10
    |
    v
Method receives a copy of 10
    |
    v
x = 100

Original number remains 10

The method changes only its local copy of the primitive value.

2. Object Example

class Employee {
    String name;
}

public class Main {
    static void changeName(Employee e) {
        e.name = "Rahul";
    }

    static void changeReference(Employee e) {
        e = new Employee();
        e.name = "Amit";
    }

    public static void main(String[] args) {
        Employee emp = new Employee();
        emp.name = "Nikhil";

        changeName(emp);
        System.out.println(emp.name);

        changeReference(emp);
        System.out.println(emp.name);
    }
}

Output

Rahul
Rahul

Explanation

emp -----------+
               |
               v
        Employee Object
        name = "Nikhil"
               |
       changeName(emp)
               |
               v
        name = "Rahul"
        Original object modified

changeReference(emp)
        |
        v
Local reference e points
to a new Employee object
        |
        v
Original emp is unchanged
name = "Rahul"

Why? The method receives a copy of the reference. It can modify the object through that reference, but assigning a new object to the local parameter does not change the caller's reference.

Key Points

  • Primitive: A copy of the value is passed.
  • Object: A copy of the reference value is passed.
  • Changing a primitive parameter does not change the original variable.
  • Changing an object's fields can affect the original object.
  • Reassigning an object parameter does not change the caller's reference.
Interview recall: Java is always pass-by-value. Objects do not make Java pass-by-reference.

6. Custom Class Example: equals() and hashCode()

import java.util.Objects;

class Employee {
    int id;
    String name;

    Employee(int id, String name) {

        this.name = name;

            return false;

        return this.id == other.id

Rule 1: If equals() returns true, hashCode() must be the same.

Simple rule: Equal objects must have equal hash codes.

Rule 2: If hashCode() is the same, objects are not necessarily equal.

class Employee {
    int id;

    Employee(int id) {
        this.id = id;
    }

    @Override
    public int hashCode() {
        return 100;

    public boolean equals(Object obj) {

            return false;

public class Main {

Both employees have the same hash code, 100, but their IDs are different.

Same hash code  -> true

Rule 3: If you override equals(), you should also override hashCode().

Consider a class where we override equals() to compare employee IDs, but do not override hashCode().

import java.util.HashSet;

class Employee {
    int id;

    Employee(int id) {
        this.id = id;
    }

    @Override
    public boolean equals(Object obj) {
        if (this == obj) {
            return true;
        }

        if (!(obj instanceof Employee)) {
            return false;
        }

        Employee other = (Employee) obj;
        return this.id == other.id;
    }

    // hashCode() is not overridden
}

public class Main {
    public static void main(String[] args) {
        HashSet<Employee> employees = new HashSet<>();

        employees.add(new Employee(101));
        employees.add(new Employee(101));

        System.out.println(employees.size());
    }
}

Override both methods using the same fields.

@Override
public boolean equals(Object obj) {
    if (this == obj) {
        return true;
    }

    if (!(obj instanceof Employee)) {
        return false;
    }

    Employee other = (Employee) obj;
    return this.id == other.id;
}

@Override
public int hashCode() {
    return Integer.hashCode(id);
}

Now both methods use the employee ID. With these methods, adding two employees with ID 101 to a HashSet results in a size of 1.

  • Equal objects: Must have the same hash code.
  • Same hash code: Objects can still be different.
  • Override equals(): Also override hashCode() consistently.
  • HashSet and HashMap: Use hash codes to find candidate locations and equality checks to identify matching keys or elements.

6.Explain `static`, `final`, `finally` and `finalize()`.

Answer / Notes

Answer

These four terms look similar, but they have different purposes in Java.

  • static: Belongs to the class rather than to each individual object.
  • final: Restricts reassignment, overriding or inheritance, depending on where it is used.
  • finally: A block generally used to execute cleanup code after a try-catch.
  • finalize(): An old method associated with garbage collection. It is deprecated for removal and should not be used in modern Java.

1. static Keyword

A static variable belongs to the class, so all objects share the same variable. A static method can be called using the class name without creating an object.

Example

class Employee {
    int id;
    static String company = "ABC";

    Employee(int id) {
        this.id = id;
    }

    static void showCompany() {
        System.out.println(company);
    }
}

public class Main {
    public static void main(String[] args) {
        Employee e1 = new Employee(101);
        Employee e2 = new Employee(102);

        System.out.println(e1.company);
        System.out.println(e2.company);

        Employee.showCompany();
    }
}

Output

ABC
ABC
ABC

Explanation

Employee class
    |
    +-- static company = "ABC"
              |
        +-----+-----+
        |           |
       e1          e2
    id = 101    id = 102

Both employees share the same company variable. Their instance variables, such as id, belong to their individual objects.

Remember: Use Employee.showCompany() to call a static method directly.

2. final Keyword

The final keyword restricts changes. Its exact meaning depends on whether it is applied to a variable, method or class.

A. final Variable

public class Main {
    public static void main(String[] args) {
        final int MAX = 100;

        System.out.println(MAX);

        // MAX = 200; // Compilation error
    }
}

Output

100

Once a final variable has been assigned, it cannot be reassigned.

B. final Method

class Parent {
    final void display() {
        System.out.println("Parent method");
    }
}

class Child extends Parent {
    // Cannot override display()
}

A final method cannot be overridden by a subclass.

C. final Class

final class Vehicle {
}

// Compilation error:
// class Car extends Vehicle { }

A final class cannot be extended. For example, Java's String class is final.

Important: final with an Object Reference

final StringBuilder sb = new StringBuilder("Java");

sb.append(" Developer"); // Allowed

// sb = new StringBuilder("Python"); // Compilation error

The reference sb cannot point to a different object, but the existing StringBuilder object can still be modified.

3. finally Block

The finally block is used for cleanup code that should generally run whether an exception occurs or not.

Example

public class Main {
    public static void main(String[] args) {
        try {
            int result = 10 / 0;
            System.out.println(result);
        } catch (ArithmeticException e) {
            System.out.println("Exception handled");
        } finally {
            System.out.println("Finally block executed");
        }
    }
}

Output

Exception handled
Finally block executed

Explanation

try block
    |
    v
Exception occurs
    |
    v
catch block handles exception
    |
    v
finally block executes

The finally block is commonly used for cleanup. For files, database connections and similar resources, try-with-resources is usually preferred when the resource implements AutoCloseable.

try-with-resources in Java

Introduced: Java 7 (2011).

Purpose: Automatically closes resources after the try block finishes, even if an exception occurs.

Requirement: The resource must implement AutoCloseable (or Closeable). Remember: try-with-resources is the feature; BufferedReader is the resource.You're right. Try-with-resources is a Java language feature, not an interface or a class. You cannot check whether try itself implements AutoCloseable. You can verify that the resource declared inside try ( ... ) implements AutoCloseable:

Example: Reading a File

import java.io.BufferedReader;
import java.io.FileReader;
import java.io.IOException;

public class Main {
    public static void main(String[] args) {
        try (BufferedReader reader =
                 new BufferedReader(new FileReader("data.txt"))) {

            System.out.println(reader.readLine());

        } catch (IOException e) {
            System.out.println("File error");
        }
    }
}

How It Works

  • Declare the resource inside try ( ... ).
  • Java automatically calls close() when the try block exits.
  • Works when the block completes normally or an exception occurs, subject to normal JVM execution.
  • The catch block handles the exception.

Why Use It Instead of finally?

finally: You generally write code to close the resource yourself.

try-with-resources: Java closes the resource automatically.

Interview Points

  • Introduced in Java 7.
  • Uses the AutoCloseable interface.
  • Reduces cleanup code and the risk of forgetting to close resources.
  • Commonly used with files, streams and JDBC resources.
Remember: Java 7 introduced try-with-resources to simplify automatic resource management.

Note: A finally block is not absolutely guaranteed to execute in every situation, such as when the JVM terminates abruptly.

Does try-with-resources work if the JVM terminates abruptly?

Answer: No, automatic resource closing is not guaranteed if the JVM terminates abruptly.

  • Normal execution: The resource is automatically closed.
  • Exception occurs: Java closes the resource before propagating the exception or entering the catch block.
  • JVM terminates abruptly: The resource might not be closed because Java may not get a chance to execute the cleanup.

Example

try (BufferedReader reader =
         new BufferedReader(new FileReader("data.txt"))) {

    System.out.println(reader.readLine());

    System.exit(0); // Abruptly terminates the JVM

} catch (IOException e) {
    System.out.println("Error occurred");
}

What Happens?

System.exit(0) initiates JVM termination. The try-with-resources cleanup is not guaranteed to run, so you must not rely on it to close the reader in this situation.

Interview Recall

try-with-resources guarantees automatic closing when execution leaves the try block normally or through an exception, but not when the JVM terminates abruptly.

4. finalize() Method

finalize() was an old method that the garbage collector could invoke before reclaiming an object. Its execution time was not guaranteed, so it was unreliable for cleanup.

Example (for understanding only)

class Demo {
    @Override
    protected void finalize() throws Throwable {
        System.out.println("Finalize called");
    }
}

public class Main {
    public static void main(String[] args) {
        Demo d = new Demo();
        d = null;

        System.gc();

        System.out.println("End of main");
    }
}

Possible Output

End of main

The message from finalize() may appear, or it may never appear. Calling System.gc() only requests garbage collection; it does not guarantee that garbage collection or finalization will happen.

Important: Finalization is deprecated for removal in modern Java. Do not use finalize() for resource cleanup. Prefer try-with-resources or explicit cleanup methods.

What is the Modern Alternative to finalize()?

finalize() is deprecated for removal. Modern Java provides safer approaches for resource cleanup.

1. AutoCloseable + try-with-resources

Use for: Files, streams, database connections and other resources that must be closed. 

import java.io.BufferedReader;
import java.io.FileReader;
import java.io.IOException;

public class Main {
    public static void main(String[] args) {
        try (BufferedReader reader =
                 new BufferedReader(new FileReader("data.txt"))) {

            System.out.println(reader.readLine());

        } catch (IOException e) {
            System.out.println("File error");
        }
    }
}

Java automatically calls close() when the try block exits normally or through an exception.

2. Cleaner

Use for: Special cases where an object needs a fallback cleanup action if it becomes unreachable. It is not a replacement for reliably closing resources. 

import java.lang.ref.Cleaner;

class Demo {
    private static final Cleaner cleaner = Cleaner.create();

    private static class Cleanup implements Runnable {
        @Override
        public void run() {
            System.out.println("Cleanup action executed");
        }
    }

    public static void main(String[] args) {
        Demo demo = new Demo();
        Cleaner.Cleanable cleanable =
                cleaner.register(demo, new Cleanup());

        cleanable.clean(); // Explicitly runs cleanup
    }
}

Output

Cleanup action executed

Cleaner can perform cleanup when explicitly requested or eventually when the registered object becomes phantom reachable. Automatic cleanup timing is not guaranteed.

Interview Recall

  • AutoCloseable + try-with-resources: Preferred for reliably closing resources.
  • Cleaner: Fallback cleanup for special cases; timing is not guaranteed.
  • finalize(): Deprecated for removal; do not use it for cleanup.
Remember: Close resources explicitly with try-with-resources. Do not depend on garbage collection to release important resources.

5. Difference Between static, final, finally and finalize()

  • static: Class-level member shared by objects.
  • final: Restricts reassignment, method overriding or class inheritance.
  • finally: Cleanup block associated with try-catch.
  • finalize(): Deprecated legacy method associated with garbage collection.

Interview Recall

static     -> Belongs to the class
final      -> Cannot be reassigned / overridden / extended,
              depending on usage
finally    -> Cleanup block after try-catch
finalize() -> Legacy GC-related method; avoid using it
Interview tip: If asked about resource cleanup, explain that finally is useful for cleanup logic, while try-with-resources is generally preferred for closing files, streams and database resources. Never rely on finalize().
