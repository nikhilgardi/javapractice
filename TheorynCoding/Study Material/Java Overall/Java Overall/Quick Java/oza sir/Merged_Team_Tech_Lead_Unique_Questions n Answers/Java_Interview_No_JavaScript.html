Java is platform-independent because the Java compiler converts source code into bytecode, which can run on any operating system that has a compatible JVM.

Primitive types store values directly, while reference types store references used to access objects.

  • Instance fields are stored as part of their objects.

4.Is Java pass-by-value or pass-by-reference? Demonstrate with an object.

Answer / Notes

Answer

Java always uses pass-by-value. A method receives a copy of the argument's value. For primitives, the actual value is copied. For objects, the reference value is copied.

1. Primitive Example

public class Main {
    static void changeValue(int x) {
        x = 100;
    }

    public static void main(String[] args) {
        int number = 10;

        changeValue(number);

        System.out.println(number);
    }
}

Output

10

Explanation

number = 10
    |
    v
Method receives a copy of 10
    |
    v
x = 100

Original number remains 10

The method changes only its local copy of the primitive value.

2. Object Example

class Employee {
    String name;
}

public class Main {
    static void changeName(Employee e) {
        e.name = "Rahul";
    }

    static void changeReference(Employee e) {
        e = new Employee();
        e.name = "Amit";
    }

    public static void main(String[] args) {
        Employee emp = new Employee();
        emp.name = "Nikhil";

        changeName(emp);
        System.out.println(emp.name);

        changeReference(emp);
        System.out.println(emp.name);
    }
}

Output

Rahul
Rahul

Explanation

emp -----------+
               |
               v
        Employee Object
        name = "Nikhil"
               |
       changeName(emp)
               |
               v
        name = "Rahul"
        Original object modified

changeReference(emp)
        |
        v
Local reference e points
to a new Employee object
        |
        v
Original emp is unchanged
name = "Rahul"

Why? The method receives a copy of the reference. It can modify the object through that reference, but assigning a new object to the local parameter does not change the caller's reference.

Key Points

  • Primitive: A copy of the value is passed.
  • Object: A copy of the reference value is passed.
  • Changing a primitive parameter does not change the original variable.
  • Changing an object's fields can affect the original object.
  • Reassigning an object parameter does not change the caller's reference.
Interview recall: Java is always pass-by-value. Objects do not make Java pass-by-reference.

6.Explain `static`, `final`, `finally` and `finalize()`.

Answer / Notes

Answer

These four terms look similar, but they have different purposes in Java.

  • static: Belongs to the class rather than to each individual object.
  • final: Restricts reassignment, overriding or inheritance, depending on where it is used.
  • finally: A block generally used to execute cleanup code after a try-catch.
  • finalize(): An old method associated with garbage collection. It is deprecated for removal and should not be used in modern Java.

class Employee {

        Employee e2 = new Employee(102);

        System.out.println(e2.company);

    id = 101    id = 102

Both employees share the same company variable. Their instance variables, such as id, belong to their individual objects.

Remember: Use Employee.showCompany() to call a static method directly.

2. final Keyword

The final keyword restricts changes. Its exact meaning depends on whether it is applied to a variable, method or class.

A. final Variable

public class Main {
    public static void main(String[] args) {
        final int MAX = 100;

        System.out.println(MAX);

        // MAX = 200; // Compilation error
    }

Output

Once a final variable has been assigned, it cannot be reassigned.

B. final Method

class Parent {
    final void display() {
        System.out.println("Parent method");
    }
}

class Child extends Parent {
    // Cannot override display()
}

A final method cannot be overridden by a subclass.

C. final Class

}

// Compilation error:
// class Car extends Vehicle { }

A final class cannot be extended. For example, Java's String class is final.

Important: final with an Object Reference

sb.append(" Developer"); // Allowed

// sb = new StringBuilder("Python"); // Compilation error

The reference sb cannot point to a different object, but the existing StringBuilder object can still be modified.

The finally block is used for cleanup code that should generally run whether an exception occurs or not.

Example

public class Main {
    public static void main(String[] args) {
        try {
            int result = 10 / 0;
            System.out.println(result);

try-with-resources in Java

Introduced: Java 7 (2011).

Purpose: Automatically closes resources after the try block finishes, even if an exception occurs.

Requirement: The resource must implement AutoCloseable (or Closeable). Remember: try-with-resources is the feature; BufferedReader is the resource.You're right. Try-with-resources is a Java language feature, not an interface or a class. You cannot check whether try itself implements AutoCloseable. You can verify that the resource declared inside try ( ... ) implements AutoCloseable:

Example: Reading a File

import java.io.BufferedReader;
import java.io.FileReader;
import java.io.IOException;

public class Main {
    public static void main(String[] args) {
        try (BufferedReader reader =
                 new BufferedReader(new FileReader("data.txt"))) {

            System.out.println(reader.readLine());

        } catch (IOException e) {
            System.out.println("File error");
        }
    }
}

How It Works

  • Declare the resource inside try ( ... ).
  • Java automatically calls close() when the try block exits.
  • Works when the block completes normally or an exception occurs, subject to normal JVM execution.
  • The catch block handles the exception.

Why Use It Instead of finally?

finally: You generally write code to close the resource yourself.

try-with-resources: Java closes the resource automatically.

Interview Points

  • Introduced in Java 7.
  • Uses the AutoCloseable interface.
  • Reduces cleanup code and the risk of forgetting to close resources.
  • Commonly used with files, streams and JDBC resources.
Remember: Java 7 introduced try-with-resources to simplify automatic resource management.

Note: A finally block is not absolutely guaranteed to execute in every situation, such as when the JVM terminates abruptly.

Does try-with-resources work if the JVM terminates abruptly?

Answer: No, automatic resource closing is not guaranteed if the JVM terminates abruptly.

  • Normal execution: The resource is automatically closed.
  • Exception occurs: Java closes the resource before propagating the exception or entering the catch block.
  • JVM terminates abruptly: The resource might not be closed because Java may not get a chance to execute the cleanup.

Example

try (BufferedReader reader =
         new BufferedReader(new FileReader("data.txt"))) {

    System.out.println(reader.readLine());

    System.exit(0); // Abruptly terminates the JVM

} catch (IOException e) {
    System.out.println("Error occurred");
}

What Happens?

System.exit(0) initiates JVM termination. The try-with-resources cleanup is not guaranteed to run, so you must not rely on it to close the reader in this situation.

Interview Recall

try-with-resources guarantees automatic closing when execution leaves the try block normally or through an exception, but not when the JVM terminates abruptly.

4. finalize() Method

finalize() was an old method that the garbage collector could invoke before reclaiming an object. Its execution time was not guaranteed, so it was unreliable for cleanup.

Example (for understanding only)

    protected void finalize() throws Throwable {
        System.out.println("Finalize called");
    }
}

        d = null;

}

End of main

The message from finalize() may appear, or it may never appear. Calling System.gc() only requests garbage collection; it does not guarantee that garbage collection or finalization will happen.

What is the Modern Alternative to finalize()?

finalize() is deprecated for removal. Modern Java provides safer approaches for resource cleanup.

1. AutoCloseable + try-with-resources

Use for: Files, streams, database connections and other resources that must be closed.

2. Cleaner

        public void run() {

    }

  • Cleaner: Fallback cleanup for special cases; timing is not guaranteed.
  • finalize(): Deprecated for removal; do not use it for cleanup.
Remember: Close resources explicitly with try-with-resources. Do not depend on garbage collection to release important resources.

9.Can static, private, final or overloaded methods be overridden? Explain each case.

Answer / Notes

1. Can static methods be overridden?

No. Static methods are hidden, not overridden, because they belong to the class rather than being dispatched based on the object's runtime type.

class Parent {
    static void display() {
        System.out.println("Parent");
    }
}

class Child extends Parent {
    static void display() {
        System.out.println("Child");
    }
}

public class Main {
    public static void main(String[] args) {
        Parent obj = new Child();
        obj.display();
    }
}

Output

Parent

Why? The method call is resolved using the reference type, Parent, not the actual object type.

2. Can private methods be overridden?

No. Private methods are not accessible to subclasses, so they cannot be overridden. A subclass can declare a separate method with the same signature.

class Parent {
    private void display() {
        System.out.println("Parent");
    }

    void callDisplay() {
        display();
    }
}

3. Can final methods be overridden?

No. A final method cannot be overridden by a subclass.

    final void display() {
        System.out.println("Parent");
    }
}

class Child extends Parent {
    // Compilation error if display() is declared here
    // with the same signature.
}

Why? The final keyword prevents subclasses from changing that method implementation.

4. Can overloaded methods be overridden?

Yes, with an important distinction. Overloading means methods have the same name but different parameter lists. A subclass can override an inherited method and also overload it with a different parameter list.

class Parent {
    void display(int x) {
        System.out.println("Parent: " + x);
    }
}

class Child extends Parent {
    @Override
    void display(int x) {
        System.out.println("Child: " + x);
    }

    void display(String text) {
        System.out.println("Child: " + text);
    }
}

public class Main {
    public static void main(String[] args) {
        Parent obj = new Child();
        obj.display(10);
        // obj.display("Java"); // Compilation error
    }
}

Output

Child: 10

Why? The display(int) method overrides the parent method. The display(String) method overloads the name in the child class, but it is not available through a Parent reference.

Interview Summary

  • static: Cannot be overridden; can be hidden.
  • private: Cannot be overridden because it is not inherited as an accessible method.
  • final: Cannot be overridden.
  • Overloaded: Overloading and overriding are different concepts. A method can be overloaded in a subclass while another method is overridden.

Why Compilation Error Occurs

Parent obj = new Child();

obj.display(10); works because display(int) exists in Parent. Since display(int) exists in Parent, the compiler accepts the call. At runtime, Java uses method overriding and dynamic method dispatch to execute the Child implementation.

obj.display("Java"); causes a compilation error because display(String) is declared only in Child, not in Parent. The compiler checks method availability using the reference type Parent.

Key Point

  • Overloading is resolved at compile time.
  • Overriding is resolved at runtime.
  • The reference type determines which methods can be called.
Remember: Static = hiding; private = not inherited as an accessible method; final = cannot override; overloaded = different parameters.

Method overriding occurs when a subclass provides its own implementation of an inherited instance method with a compatible signature.

11.Explain encapsulation, inheritance, polymorphism and abstraction with examples.

Answer / Notes

1. Encapsulation

Definition: Encapsulation means keeping data and the methods that operate on that data together in a class, while controlling access to the data.

Real-world example: A bank account protects its balance. You cannot directly change the balance; you use methods such as deposit() and withdraw().

Java Example

class BankAccount {
    private double balance;

    public void deposit(double amount) {
        if (amount > 0) {
            balance += amount;
        }
    }

    public double getBalance() {
        return balance;
    }
}

public class Main {
    public static void main(String[] args) {
        BankAccount account = new BankAccount();

        account.deposit(5000);

        System.out.println(account.getBalance());
    }
}

Output

5000.0

Explanation

  • private balance cannot be accessed directly from outside the class.
  • deposit() controls how the balance is updated.
  • getBalance() provides controlled access to the balance.

Remember: Encapsulation = Protect data and control access.

2. Inheritance

Definition: Inheritance allows a child class to acquire accessible fields and methods from a parent class.

Real-world example: A car is a type of vehicle. It can use common vehicle behavior and also have its own features.

Java Example

class Vehicle {
    void start() {
        System.out.println("Vehicle starts");
    }
}

class Car extends Vehicle {
    void drive() {
        System.out.println("Car is driving");
    }
}

public class Main {
    public static void main(String[] args) {
        Car car = new Car();

        car.start();
        car.drive();
    }
}

Output

Vehicle starts
Car is driving

Explanation

  • Vehicle is the parent class.
  • Car is the child class.
  • extends establishes inheritance.
  • Car can use the inherited start() method and its own drive() method.

Remember: Inheritance = Reuse and extend existing class behavior.

3. Polymorphism

Definition: Polymorphism means "one name, many forms." The same method call can produce different behavior depending on the object.

Real-world example: The command "make sound" produces different sounds for a dog and a cat.

Java Example: Runtime Polymorphism

class Animal {
    void makeSound() {
        System.out.println("Animal makes a sound");
    }
}

class Dog extends Animal {
    @Override
    void makeSound() {
        System.out.println("Dog barks");
    }
}

class Cat extends Animal {
    @Override
    void makeSound() {
        System.out.println("Cat meows");
    }
}

public class Main {
    public static void main(String[] args) {
        Animal a;

        a = new Dog();
        a.makeSound();

        a = new Cat();
        a.makeSound();
    }
}

Output

Dog barks
Cat meows

Explanation

  • Animal a is a parent-class reference.
  • It can refer to a Dog object or a Cat object.
  • The overridden makeSound() implementation is selected according to the actual object's class at runtime.

Remember: Runtime polymorphism = Method overriding.

Also remember: Method overloading is compile-time polymorphism; Java selects the applicable overloaded method at compile time.

4. Abstraction

Definition: Abstraction means exposing essential operations while hiding the implementation details.

Real-world example: You drive a car using the steering wheel and pedals without needing to understand every internal engine operation.

Java Example: Abstract Class

abstract class Payment {
    abstract void pay(double amount);
}

class UpiPayment extends Payment {
    @Override
    void pay(double amount) {
        System.out.println("Paid " + amount + " using UPI");
    }
}

public class Main {
    public static void main(String[] args) {
        Payment payment = new UpiPayment();

        payment.pay(1000);
    }
}

Output

Paid 1000.0 using UPI

Explanation

  • abstract class Payment defines the general payment concept.
  • pay() declares what a payment implementation must do, without specifying how.
  • UpiPayment provides the actual implementation.
  • The caller uses the Payment abstraction without needing to know its internal implementation.

Remember: Abstraction = Show what an object can do; hide how it does it.

5. Difference Between the Four OOP Principles

  • Encapsulation: Protect data and control access.
  • Inheritance: Reuse and extend parent-class behavior.
  • Polymorphism: The same method call can behave differently for different objects.
  • Abstraction: Expose essential behavior and hide implementation details.
Interview recall:
Encapsulation = Data protection.
Inheritance = Code reuse.
Polymorphism = Many forms.
Abstraction = Hide implementation details.

1. Interface — Defines a Contract

A contract means a rule that a class agrees to follow. An interface defines what methods a class must provide.

Example: Every animal must provide its own sound.

interface Animal {
    void sound();
}

class Dog implements Animal {
    public void sound() {
        System.out.println("Dog barks");
    }
}

class Cat implements Animal {
    public void sound() {
        System.out.println("Cat meows");
    }
}

Output

Dog barks
Cat meows

How does the contract work?

  • Animal says that a sound() method must be provided.
  • Dog provides the dog-specific sound.
  • Cat provides the cat-specific sound.
  • If a concrete class fails to implement the required abstract method, Java reports a compilation error.
Remember: Interface = What must be done.

2. Abstract Class — Shares Common Data and Methods

An abstract class provides common data and implemented methods that child classes can reuse. It can also declare abstract methods that child classes must implement.

Example: All animals have a name and can eat.

        this.name = name;

    }
}

Tommy barks
Kitty is eating
Kitty meows

How does common sharing work?

  • Animal provides the shared name field.
  • Animal provides the shared eat() method.
  • Dog and Cat reuse these without rewriting them.
  • Each child class implements its own sound() method.
Remember: Abstract class = What is common + what child classes must implement.

13.Why does Java not support multiple inheritance through classes?

Answer / Notes

1. What Is Multiple Inheritance?

Multiple inheritance means a child class inherits from more than one parent class. 

// Java does not allow this

class A {
    void show() {
        System.out.println("A");
    }
}

class B {
    void show() {
        System.out.println("B");
    }
}

// Compilation error: Java does not allow
// a class to extend two classes directly.
// class C extends A, B { }

2. The Problem: Which Method Should Java Call?

Imagine a language that allows this inheritance structure:

        A       B
         \     /
          \   /
            C

Both parent classes have a method named show(). If class C inherits both methods, which implementation should it use?

  • Should it call A's show()?
  • Should it call B's show()?

This creates ambiguity if the language does not define a clear rule for choosing between the inherited implementations.

3. The Diamond Problem

        A
       / \
      B   C
       \ /
        D

Suppose A defines a method called show(). Classes B and C inherit A and provide different implementations of show(). If D inherits from both B and C, it may be unclear which implementation D should use.

This is called the Diamond Problem, because the inheritance structure resembles a diamond.

4. How Does Java Allow Similar Flexibility?

Java allows a class to extend one class and implement multiple interfaces. 

interface Camera {
    void takePhoto();
}

interface Phone {
    void makeCall();
}

class SmartPhone implements Camera, Phone {

    public void takePhoto() {
        System.out.println("Taking photo");
    }

    public void makeCall() {
        System.out.println("Making call");
    }
}

Output when both methods are called:

Taking photo
Making call

This allows a class to follow multiple interface contracts without inheriting implementation from multiple classes.

Interview answer: Java does not support multiple inheritance through classes to avoid ambiguity and complexity when inheriting state and method implementations from multiple parent classes. Instead, Java allows a class to implement multiple interfaces.

How Is the Diamond Problem Resolved in Java?

1. Diamond Structure

        A
       / \
      B   C
       \ /
        D
  • A is the parent.
  • B and C inherit from A.
  • D inherits from both B and C.

If B and C provide different implementations of the same method, D could face a conflict over which implementation to use.

2. Complete Java Example Using Interfaces

interface B {
    default void show() {
        System.out.println("B's show()");
    }
}

interface C {
    default void show() {
        System.out.println("C's show()");
    }
}

class D implements B, C {

    // Resolve the conflict by overriding show()
    @Override
    public void show() {
        System.out.println("D resolves the conflict");

        B.super.show();
        C.super.show();
    }
}

public class Main {
    public static void main(String[] args) {
        D obj = new D();
        obj.show();
    }
}

4. How Is the Conflict Resolved?

Step 1: Interface B provides its own show() implementation.

default void show() {
    System.out.println("B's show()");
}

Step 2: Interface C also provides its own show() implementation.

default void show() {
    System.out.println("C's show()");
}

Step 3: Class D implements both interfaces. Java requires D to resolve the conflicting default methods.

@Override
public void show() {
    System.out.println("D resolves the conflict");
}

Step 4: D can explicitly call either or both interface implementations.

B.super.show(); // Calls B's implementation
C.super.show(); // Calls C's implementation

D could instead provide completely new behavior without calling either interface method.

1. Overview

Concept Relationship Meaning

2. Inheritance

Inheritance allows one class to acquire accessible fields and methods from another class. It represents an IS-A relationship.

Types of Inheritance

  • Single: One child extends one parent.
  • Multilevel: A class extends a class that already extends another class.
  • Hierarchical: Multiple child classes extend the same parent.
  • Multiple: One class inherits from multiple parents. Java does not support this through classes, but a class can implement multiple interfaces.
  • Hybrid: A combination of inheritance types. Java can achieve certain hybrid structures using interfaces.

}

    void bark() {
        System.out.println("Dog barks");
    }
}

public class Main {
    public static void main(String[] args) {
        Dog dog = new Dog();
        dog.eat();
        dog.bark();
    }
}

Output

Animal eats
Dog barks

Explanation: Dog IS-A Animal, so Dog inherits the accessible eat() method.

3. Aggregation — Weak HAS-A Relationship

Aggregation means one object refers to another object, but the referenced object can exist independently of the first object.

Example: Department and Teacher

    String name;

    Teacher(String name) {
        this.name = name;
    }
}

    private Teacher teacher;

    Department(Teacher teacher) {
        this.teacher = teacher;
    }

        System.out.println(teacher.name);
    }
}

    public static void main(String[] args) {
        Teacher t = new Teacher("Ravi");

        Department d = new Department(t);
        d.showTeacher();
    }
}

Output

Ravi

Explanation:

  • Teacher is created separately from Department.
  • Department receives an existing Teacher object.
  • The Teacher can continue to exist even if the Department object is no longer used.

Remember: Aggregation represents a weak ownership relationship.

4. Composition — Strong HAS-A Relationship

Composition means an object strongly owns another object as part of its structure. The contained object's lifecycle is generally tied to the owner in the intended design.

    void show() {
        System.out.println("Room exists");
    }
}

        room = new Room();
    }

        room.show();
        System.out.println("House exists");
    }
}

public class Main {
    public static void main(String[] args) {
        House house = new House();
        house.showHouse();
    }
}

Output

Room exists
House exists

Explanation:

  • House creates and owns its Room in this example.
  • The Room is managed as part of the House's structure.
  • This illustrates strong ownership, rather than passing an independently created Room into House.

Remember: Composition represents a strong ownership relationship. Java does not automatically destroy a contained object when its owner is destroyed; object reachability and garbage collection determine when memory can be reclaimed.

A default method is a method inside an interface that has a method body. It uses the default keyword.

}

    }
}

Output

Showing bank balance

Explanation: User does not override showBalance(), so it inherits and uses the default implementation from Bank.

A static method belongs to the interface itself. Call it using the interface name, not an implementing class object.

    static void showMessage() {
        System.out.println("Welcome to the bank");
    }
}

public class Main {
    public static void main(String[] args) {

    }
}

Output

Welcome to the bank

Default Method Static Method
Uses the default keyword. Uses the static keyword.

4. How Are Conflicting Default Methods Resolved?

If a class implements two interfaces that provide default methods with the same signature, the class must override that method to resolve the conflict.

Example

interface ICICIBank {
    default void showBalance() {
        System.out.println("ICICI Bank balance");
    }
}

interface UCOBank {
    default void showBalance() {
        System.out.println("UCO Bank balance");
    }
}

class User implements ICICIBank, UCOBank {

    @Override
    public void showBalance() {
        System.out.println("User chooses both banks");

        UCOBank.super.showBalance();
    }
}

public class Main {
    public static void main(String[] args) {
        User u = new User();
        u.showBalance();
    }
}

User chooses both banks
ICICI Bank balance
UCO Bank balance

  • Both interfaces provide a default implementation of showBalance().
  • Java cannot automatically choose which implementation to use.
  • The User class overrides showBalance() to resolve the conflict.
  • ICICIBank.super.showBalance() calls the ICICI default method.
  • UCOBank.super.showBalance() calls the UCO default method.
Interview Tips:

  • Static method = interface method called using the interface name.
  • Conflicting default methods = the implementing class must override the method.
  • Use InterfaceName.super.methodName() to call a specific interface's default implementation.

25.How do you design a truly immutable class?

Answer / Notes

How Do You Design a Truly Immutable Class in Java?

An immutable class is a class whose object state (Object state = Current data stored inside an object.)cannot be changed after the object is created. 

Object state means the current values of an object's variables (fields).

Example:
class Student {
    int age = 25;
    String name = "Rahul";
}


Here, the object's state is:
- age = 25
- name = "Rahul"
In simple words: Object state = Current data stored inside an object.

Once we create an object, its values cannot be modified.

1. Rules to Create an Immutable Class

  1. Declare the class as final so it cannot be extended.
  2. Declare all instance variables as private.
  3. Declare all instance variables as final.
  4. Do not provide setter methods.
  5. Initialize variables through the constructor.
  6. If a variable refers to a mutable object, use defensive copying when receiving and returning it.

2. Simple Example of an Immutable Class

final class Employee {

    private final int id;
    private final String name;

    public Employee(int id, String name) {
        this.id = id;
        this.name = name;
    }

    public int getId() {
        return id;
    }

    public String getName() {
        return name;
    }
}

public class Main {
    public static void main(String[] args) {

        Employee emp = new Employee(101, "Rahul");

        System.out.println(emp.getId());
        System.out.println(emp.getName());
    }
}

Output

101
Rahul

Explanation

  • final class Employee – cannot be extended.
  • private final variables – cannot be reassigned after initialization.
  • No setter methods – values cannot be changed through setters.
  • Constructor initializes the values.

3. Important: What If the Class Contains a Mutable Object?

Consider the following example using the mutable Date class. 

import java.util.Date;

final class Employee {

    private final String name;
    private final Date joiningDate;

    public Employee(String name, Date joiningDate) {
        this.name = name;
        this.joiningDate = joiningDate;
    }

    public Date getJoiningDate() {
        return joiningDate;
    }
}

Problem: This class is not truly immutable.

  • Date is a mutable object.
  • Someone can modify the original Date object passed to the constructor.Constructor: date.setTime(0); — modifies the original Date object passed to the constructor.
  • Someone can also modify the Date object returned by the getter.Getter: emp.getJoiningDate().setTime(0); — modifies the Date object returned by the getter.
  • Therefore, the internal joiningDate value can change.

Example of the Problem

Defensive copying means creating a separate copy of a mutable object so external code cannot modify the original object's state. 

import java.util.Date;

final class Employee {

    private final String name;
    private final Date joiningDate;

    public Employee(String name, Date joiningDate) {
        this.name = name;
        this.joiningDate = new Date(joiningDate.getTime());
    }

    public String getName() {
        return name;
    }

    public Date getJoiningDate() {
        return new Date(joiningDate.getTime());
    }
}

public class Main {
    public static void main(String[] args) {

        Date date = new Date();

        Employee emp = new Employee("Rahul", date);

        // Original Date changes
        date.setTime(0);

        // Returned Date changes
        Date returnedDate = emp.getJoiningDate();
        returnedDate.setTime(0);

        System.out.println(emp.getName());
        System.out.println(emp.getJoiningDate());
    }
}

Explanation

  • Constructor creates a copy of the incoming Date object.
  • Getter returns another copy of the Date object.
  • External code cannot modify the Employee's internal Date object.

27.Explain the `equals()` and `hashCode()` contracts.

Answer / Notes

Explain the equals() and hashCode() Contracts

1. What is equals()?

The equals() method compares two objects based on their logical content rather than their memory references.

2. What is hashCode()?

The hashCode() method returns an integer value for an object. It is used by hash-based collections like HashMap and HashSet to identify the bucket where an object should be stored.

3. What are the equals() and hashCode() Contracts?

Java defines rules that must be followed when overriding equals() and hashCode().

  1. Equal objects must have the same hash code.

    If two objects are equal according to equals(), their hashCode() values must also be equal.

  2. Same hash code does not mean objects are equal.

    Two different objects can have the same hash code. This is called a hash collision.

  3. Override both methods together.

    If you override equals(), you should also override hashCode() to maintain the contract.

4. Practical Example


import java.util.Objects;

class Employee {
    private int id;
    private String name;

    public Employee(int id, String name) {
        this.id = id;
        this.name = name;
    }

    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;

        if (!(obj instanceof Employee)) return false;

        Employee other = (Employee) obj;

        return id == other.id &&
               Objects.equals(name, other.name);
    }

    @Override
    public int hashCode() {
        return Objects.hash(id, name);
    }
}

5. Testing the Example


Employee e1 = new Employee(101, "Rahul");
Employee e2 = new Employee(101, "Rahul");

System.out.println(e1.equals(e2));
// true

System.out.println(e1.hashCode() == e2.hashCode());
// true

Both objects have the same id and name. Therefore, equals() returns true and both objects have the same hash code.

6. What Happens If We Override Only equals()?

If we override equals() but do not override hashCode(), two logically equal objects may have different hash codes. HashSet or HashMap may then fail to identify them as equal keys.

7. Interview Answer

The equals() and hashCode() contract states that if two objects are equal according to equals(), they must have the same hash code. However, two objects having the same hash code does not necessarily mean they are equal. Therefore, whenever we override equals(), we should also override hashCode().

As a result, HashMap may not be able to find the key using get() or remove(), even though the key is still present in the map.

2. Practical Example


import java.util.HashMap;
import java.util.Map;
import java.util.Objects;

    String name;

        this.id = id;
        this.name = name;

    public boolean equals(Object obj) {

        if (!(obj instanceof Employee)) return false;

        Employee other = (Employee) obj;

        return id == other.id &&
               Objects.equals(name, other.name);

    @Override
    public int hashCode() {
        return Objects.hash(id, name);
    }

public class Main {

  6. The entry may still be stored in the original bucket, so lookup fails.

Java HashMap stores the key's hash value inside its internal entry when inserting it.

Interview Takeaway

Changing a key's equals() or hashCode()-related fields after insertion can make a HashMap entry practically inaccessible through normal lookup operations such as get() and remove().

How to Avoid Mutable HashMap Key Problems

1. Recommended Solution: Use an Immutable Class

The best way to avoid problems caused by modifying a HashMap key is to use an immutable Java class as the key.

2. Create an Immutable Employee Class


import java.util.Objects;

final class Employee {

    private final int id;
    private final String name;

    public Employee(int id, String name) {
        this.id = id;
        this.name = name;
    }

    public int getId() {
        return id;
    }

    public String getName() {
        return name;
    }

    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;

        if (!(obj instanceof Employee)) return false;

        Employee other = (Employee) obj;

        return id == other.id &&
               Objects.equals(name, other.name);
    }

    @Override
    public int hashCode() {
        return Objects.hash(id, name);
    }
}

3. Use Employee as a HashMap Key


import java.util.HashMap;
import java.util.Map;

public class Main {

    public static void main(String[] args) {

        Map<Employee, String> map = new HashMap<>();

        Employee emp = new Employee(101, "Rahul");

        map.put(emp, "Developer");

        System.out.println(map.get(emp));
        // Developer

        // Cannot modify emp.id or emp.name
        // emp.id = 102; // Compile-time error

        System.out.println(map.get(emp));
        // Developer
    }
}

final class Prevents inheritance.
private fields Prevents direct external access.
final fields Prevents reassignment after construction.

This example is safe because int is a primitive type and String is immutable.

6. Interview Answer

Use immutable objects as HashMap keys. Make the class final, keep fields private and final, provide no setters, and implement equals() and hashCode() consistently. This prevents the key's equality-related state from changing after insertion.

How Do You Compare Objects for Identity Versus Logical Equality?

1. Object Identity (==)

The == operator checks whether two reference variables point to the same object in memory. 


String s1 = new String("Java");
String s2 = new String("Java");

System.out.println(s1 == s2); // false

Reason: Both variables refer to two different String objects, even though their contents are the same.

2. Logical Equality (equals())

The equals() method checks whether two objects have the same logical content or values, provided the class implements equals() accordingly. 


String s1 = new String("Java");
String s2 = new String("Java");

System.out.println(s1.equals(s2)); // true

Reason: Both String objects contain the same text, "Java".

3. Practical Example Using a Custom Class


class Employee {
    int id;
    String name;

    Employee(int id, String name) {
        this.id = id;
        this.name = name;
    }

    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;

        if (!(obj instanceof Employee)) return false;

        Employee other = (Employee) obj;

        return id == other.id;
    }
}

public class Main {
    public static void main(String[] args) {

        Employee e1 = new Employee(101, "Rahul");
        Employee e2 = new Employee(101, "Rahul");

        System.out.println(e1 == e2);
        // false

        System.out.println(e1.equals(e2));
        // true
    }
}

Explanation:

  • e1 == e2 returns false because they are two different objects.
  • e1.equals(e2) returns true because both objects have the same ID.

4. Difference Between == and equals()

== equals()
Checks object identity. Checks logical equality when properly overridden.
Compares object references. Compares object content or values, depending on implementation.
Operator in Java. Method from the Object class.
Cannot be overridden. Can be overridden.

5. Interview Answer

The == operator compares object references to check whether two variables point to the same object, whereas equals() compares the logical content of objects when the method is properly overridden.
